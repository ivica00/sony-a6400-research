## Bounded probe and original path

The helper accepts only the compiled literal `? GETHOME\r` (10bytes), not arbitrary command text. Original libMWF standard table entry `?` points to ExecCmdHelp; instruction inspection confirms its two-argument path searches/prints help rather than invoking GETHOME. Before publishing, the helper checks the live table name/help text/callback address, parser cursor0, command mode0, code prefix, GOT, ring topology, complete backing mapping and stable header/object/global observations.

It writes the ten payload bytes into free input-ring space, rechecks parser/cursor state, then publishes one four-byte input write cursor. Publication is reported separately from execution success. Checks use the native single-producer protocol; they are not an exclusive-producer certificate or multi-producer CAS.

Echo was enabled. A new probe-specific output-ack mode permits partially consumed input only while its write cursor equals this probe's published endpoint. This allows draining echo without waiting for the entire command to be read. Bounds, expected output cursors and repeated live identity checks remain enforced. Every output chunk is saved, fsync'ed and readback-verified before acknowledgement. Changed/foreign input endpoint rejects that mode. Input read cursors are never modified by the helper.
