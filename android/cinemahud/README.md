# CinemaHUD Android

Native Flutter landscape monitor for Sony ILCE-6400. UI and PTP readback behavior
follow the local CinemaHUD implementation. This is a Flutter UI, not a WebView.

## Connections

- **PC BRIDGE (current physical test):** camera stays on Windows in PC Remote,
  Python CinemaHUD server stays on 127.0.0.1:8080. Connect Xiaomi through ADB and
  run `adb reverse tcp:8080 tcp:8080`. In the app, MENU -> CONNECT -> PC BRIDGE,
  address `http://127.0.0.1:8080`.
- **USB CAMERA (implemented; physical OTG test pending):** connect camera directly
  to phone via an OTG-capable adapter, camera set to PC Remote. MENU -> CONNECT ->
  USB CAMERA; grant the Android USB permission. No PC/server is needed in this mode.

The PC server intentionally listens only on loopback. Entering a LAN address
alone does not make that server reachable; use the USB reverse tunnel above.
No Wi-Fi debugging or network-wide server exposure is enabled by this project.
On Windows, `scripts/launch_cinemahud_android.ps1` recreates this USB tunnel and opens
the installed app; `-Install` also installs the APK from `dist/cinemahud-android/`.

## Features

Real JPEG liveview, camera-driven shutter/iris/ISO/EV selectors, exact readback
confirmation, legacy Sony 0x9207 notches, frame and thirds guides, center cross,
2x magnification, scope crop, display flips, enhancement and focus peaking.
Enhancement now uses the Qualcomm SGSR1 reconstruction algorithm on the GPU; see the GPU update below.
Grey scope/NR/focus/record/capture buttons are not implemented.
No recording or still capture is performed by tests.

## Implementation

- `lib/main.dart`: responsive landscape UI and camera menus.
- `lib/camera_controller.dart`: serialized user changes, liveview, PC transport.
- `lib/sony_ptp.dart`: bounded Sony descriptor parser, handshake, control/readback.
- `android/app/src/main/kotlin/.../MainActivity.kt`: USB host permission and bulk PTP
  containers on one executor. Camera decisions are not implemented in native glue.
- `shaders/monitor.frag`: SGSR1, float 3D LUT, input zebra and focus peaking.
- `shaders/flow.frag`, `shaders/interpolate.frag`: GPU flow and midpoint generation.

Foreground app keeps the display awake. Backgrounding releases its connection;
reconnect from MENU. USB disconnects/transport failures stop the connection.
A value skipped by the lens/mode is reported as unconfirmed, never exact success.

## WSL build

Build tools used for this task: official Flutter stable 3.47.9, Dart 3.13.7,
Android SDK platform 36, build tools 36.0.0, NDK 28.2 (requested by Flutter), Java 21.
Flutter SDK and Android SDK are under `~/cinemahud-tools/` in Ubuntu WSL.
Gradle wrapper/plugin versions are generated by that Flutter release and committed.

```sh
export ANDROID_HOME="$HOME/cinemahud-tools/android-sdk"
export PATH="$HOME/cinemahud-tools/flutter/bin:$PATH"
flutter pub get
flutter analyze
flutter test
flutter build apk --release --target-platform android-arm64 --target lib/main.dart
```

The release is currently signed with the local development/debug key for device
testing; it is not a Play Store release. No signing secrets are checked in.

## Device test

Xiaomi 14 (model 23127PN0CG), Android API 35; USB ADB authorized by the operator.
Integration test `integration_test/device_smoke_test.dart` is a separate test APK:
it opens exposure menus, changes shutter/aperture/EV/ISO, checks actual camera
readbacks and restores the value read at the start of each test. It does not
switch camera modes, install camera firmware, or touch the camera SD card.
Physical result: on-device Flutter integration test passed all four menu
roundtrips: 1/100 -> 1/125 -> 1/100, f/2.8 -> f/3.2 -> f/2.8,
EV 0 -> +0.3 -> 0, Auto ISO -> 800 -> Auto ISO. A 1024x576 JPEG stream was
observed in the final test (an earlier capture was 1024x680; camera state varies).
Four local Flutter tests also pass; static analysis has no issues.
The first Android command test exposed a chunked HTTP request mismatch with
the Python server; explicit request Content-Length fixed it, and the complete
on-device menu test passed after the fix.

Final installed APK: `dist/cinemahud-android/CinemaHUD-Android-arm64.apk`,
17.2 MB, built with WSL. The final release APK excludes the test entrypoint.
Receipts/screenshots: `artifacts/hardware/cinemahud-android-xiaomi14/` in the repo.

## 1.1.0 GPU/color update

- ENH: Qualcomm SGSR1, adapted under BSD-3-Clause to Flutter runtime GLSL.
  It runs on the phone's Adreno 750 through Impeller/Vulkan. `textureGather` is
  emulated at texel centers for runtime-effect compatibility; this is not a
  benchmark-equivalent copy of the vendor's native gather implementation.
- MOTION: app-owned GPU optical flow and 2x-target midpoint synthesis. This is
  NOT Qualcomm's proprietary AFME nor the ANF SDK. SGSR2/ANF scene-depth/jitter
  inputs are not available in a Sony JPEG stream. No driver/root modifications.
- Display synthesis runs once at source resolution before SGSR/LUT, keeping the
  video texture pipeline on GPU. Hud/text is composed afterwards, never interpolated.
- Input and output rates are separate. The output counter tracks distinct painted
  compositor stages and excludes repeated vsync paints. It is not a hardware
  present-to-glass timestamp benchmark. Input cadence, load, motion range and
  confidence can reduce the achieved multiplier; 2x is the scheduling target.
- Motion search is bounded to +/-15 source pixels with confidence and cut/occlusion
  fallback to the real current frame. Fast motion and boundaries may have artifacts.
  Enabling interpolation adds display delay (roughly half an input interval plus
  synthesis time); disable it when minimum monitor latency is more important.
- 709 toggles the selected S-Log2-to-709 LUT. User Phantom LUTs already include their
  conversion, so the app does not apply another S-Log/709 transform before them.
- Ten supplied Phantom .cube variants are bundled locally; MENU selects a LUT,
  adjusts strength, or imports a new 3D .cube via Android's system document picker.
  LUT input must match the camera gamma/gamut; no Picture Profile writes are made.
- 3D CUBE parser supports size 2–65 and domains; full float atlas, explicit trilinear
  sampling, 8 MB import bound. Float values are retained until final SDR display.
- ZEBRA meters incoming JPEG signal before LUT/709; threshold 50–100% in MENU.
  This is a display-signal aid, not a RAW sensor clipping/IRE calibration claim.
- User LUT assets are ignored by Git. For a clean local rebuild, copy the user's
  .cube files into `assets/user_luts/`; do not publish or redistribute the pack.
- Qualcomm license ships in the APK and is viewable under MENU -> LICENSES.

Validated on Xiaomi 14: seven local tests, exact identity/swap LUT pixel tests,
all ten 33^3 LUTs against CPU samples, zebra stripes, synthetic 4-pixel translation
with lower midpoint MSE than both repeat and blend, and live camera rendering.
Unrestricted release samples: about 20–23 input fps / 36–46 painted stages per
second with SGSR1, LUT, zebra and motion enabled. Flow+midpoint wall time was about
1.6–3 ms in those samples. These are PC-bridge samples, not a universal FPS promise.
GPU receipts: `artifacts/hardware/cinemahud-android-gpu/` in the repository root.

## 1.2.0 low latency update

- Camera to PC: publish completed JPEG immediately into one latest-frame slot;
  MJPEG wakes on a new sequence, without the old 33 ms periodic send. The WPD
  owner keeps serial PTP transactions but can fetch frames during setting settle
  waits. Shorter bounded retries apply only to the live server's empty frames.
- PC bridge to Android: persistent sequence-aware `/frame.jpg?after=N` returns
  the newest frame once available, or 204 on timeout. Both TCP ends use NODELAY.
  The response stream ID prevents an old sequence from blocking after restart.
  Bridge status reads are independent of video. Older bridges still work with
  the legacy endpoint, but lack newest-sequence wait.
- Camera to phone: fetch and JPEG decode overlap, with one newest pending frame
  replacing any older pending frame. No fixed 25 ms post-frame delay. USB PTP
  transactions remain serialized by the Android executor. Direct OTG transport
  was not physically tested in this cycle.
- MENU -> LOW LATENCY (default) bypasses MOTION. SGSR, LUT and zebras remain
  available; MOTION can be enabled for smoother display at the cost of delay.

Measurements (Xiaomi 14, real camera PC bridge, 1024x576): about 24–25 displayed
stages/s with MOTION disabled; PC GetObject p50 roughly 6–8 ms; phone JPEG decode
roughly 7–16 ms depending on window; typical PC frame age at send roughly 0.1–0.2
ms (tail varies); median pending decode queue near zero in the overlapping run.
On PC, immediate local HTTP frame request/read fell from roughly 15 ms to 0.2 ms
with persistent connections. This does not include USB bridge one-way time.
The long-poll request time includes waiting for a new camera frame; do not
interpret it as transport latency. Sensor/exposure, firmware buffering and
screen scanout are not measured by these stage counters. A physical timer or LED
reference visible to camera and display is required for sensor-to-glass timing.

Receipts: `artifacts/hardware/cinemahud-latency/`. Python suite: 895 passed;
Flutter: 8 passed, analysis clean. No firmware, USB mode or SD changes.
